# Extract the existing system

Start with working precedent. Inspect representative pages and their source before
inventing a new taxonomy. Record the real values for spacing, type, width, color and
radius; count recurring values and retain the dominant host scale. Do not replace
brand choices merely because the Pagesystem samples use another palette.

Group pages by visitor task and structural contract. A shared visual treatment is
not enough to make two pages the same type. Distinguish systems, components and
semantic elements. For each candidate component record its job, inputs, states,
accessibility, responsive rules and where it is already used.

Choose one canonical owner for each fact and behavior. Keep content separate from
presentation. Extract the smallest useful interface and migrate a working caller
first. Check it at relevant sizes and states before moving the next caller. Preserve
live URLs and indexing behavior unless the task explicitly calls for changes.

Deliver the token source, reusable implementation, mapped page contracts, and an
inventory of migrated and remaining callers. Explain any unresolved differences
with quoted source evidence. Keep a before/after revision and report actual tests.

Read [the foundations](references/foundations.md) before making or reviewing visual
decisions. Typography, line length, density, page gutters, panel padding and sibling
spacing are required parts of the contract. Map roles to the host's tokens; do not
make up values per component. Do not add decorative section numbers such as
`03 / PRINCIPLES`; number only real steps, records, quantities or references.

Read [the catalog](references/catalog.md), a one-line index of every page system,
component and element, then open only the entry files you need: each holds one
entry's contract, HTML and variants. Read [the implementation guide](references/implementation.md)
before shipping components: it explains the shared stylesheet and behaviors, which
are copied into the project, never read whole. All are generated from the Pagesystem library.
Preserve the host product's visual identity; the house palette is an example,
not a requirement. Do not claim access to a Pagesystem MCP server: it is not built.
