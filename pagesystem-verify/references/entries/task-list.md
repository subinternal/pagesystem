# Task list (task-list)

Kind: component. A checkable list of the tasks an agent works through, with a progress count, the task in progress and expandable subtasks.

Task: Follow which task an agent is on, check tasks off, and open a task to see and complete its subtasks.

Elements: [text](text.md), [input](input.md), [button](button.md).

Category: agent.

Native behavior: task-list. It needs pagesystem.js (see ../implementation.md).

## content

- A titled list with a done count and a progress ring.
- Top-level tasks, each with a checkbox, a name and a status line.
- Optional subtasks under a task, with their own checkboxes.
- Optional blocked tasks with the reason and who they are waiting on.
- Sample tasks are labeled as samples.
- Each task has a detail card with assignee, due date, subtasks with a progress meter, recent activity and linked items.

## states

- in progress with one active task
- task with some subtasks done (mixed)
- task card open (one at a time)
- task card closed
- blocked task
- unblocked
- complete
- list collapsed to its summary

## responsive

- Task names wrap and the status line drops under the name at narrow widths.
- Rows keep the house control height so checkboxes, expand and unblock controls stay easy to hit.
- Keep essential text at body size under text enlargement.

## checks

- The count, ring and status line derive from the same checkbox state.
- A task with subtasks is checked only when all of them are, mixed when some are, and checking it checks them all.
- The first unchecked, unblocked task is the one in progress; blocked tasks are skipped, not hidden.
- A blocked task cannot be checked until it is unblocked; its reason is linked to its checkbox.
- Arrow keys, Home and End move between checkboxes; Space checks; the header button collapses the list.
- Changes are announced in a status message and no state is stored.
- Checking a task off never opens its card; the card opens only from its disclosure button, and Escape closes it and returns focus to that button.
